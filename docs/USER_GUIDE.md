# 效能评估系统 —— 用户操作手册

系统按两类角色授权。登录后左侧菜单只显示当前角色可访问的模块。

| 角色 | 默认账号 | 典型工作 |
|---|---|---|
| 系统管理员 | `admin` | 用户、角色、系统参数、审计日志、算法基准、部署检查 |
| 评估人员 | `evaluator` | 项目、指标体系、数据接入（**数据库抽取 + 文件导入**：数据源 / 数据批次 / 数据快照）、任务配置、算法执行、结果复核 / 发布 / 横向对比、结果分析（不含报告导出；报告导出仅系统管理员） |

> 评估人员共 **9 个菜单码**（`dashboard`、`project`、`indicator`、`dataSource`、`dataBatch`、`snapshot`、`task`、`result`、`baseline`），
> 对应侧栏的 综合驾驶舱 / 项目管理 / 指标体系 / 数据接入（数据源管理、数据批次、数据快照）/ 评估工作台 / 评估任务 / 评估结果 / 算法基准，
> 即「数据接入」下三个子项齐全——**数据库抽取（数据源管理）与文件导入（数据批次）两种接入方式评估人员都能用**；
> **不再出现「报告导出」**，直接访问 `/reports` 也进不去；系统管理员共 **14 个菜单码**，含「报告导出」。
> 评估人员共 **29 项权限**，其中数据源相关的 `data:source:list` / `data:source:create` / `data:source:update` /
> `data:source:test` / `data:source:extract` 五个码均已授予。
> 注意：**「评估结果」页的导出 Excel / Word / PDF 评估人员仍然可用**（由 `result:export` 控制，与报告模块权限无关），
> 只有「报告导出记录」页面与报告模块接口仅系统管理员可用。

## 一、登录与账号

1. 打开 <http://127.0.0.1:5173>，输入用户名与密码。
2. 忘记密码请联系系统管理员重置；连续登录失败 5 次账号将被锁定 15 分钟。
3. 右上角头像菜单 → **修改密码**，修改成功后需重新登录。

> **登录态是会话级的**：令牌保存在浏览器当前标签页的会话存储（`sessionStorage`）中，不再长期留存在本机。
>
> - **关闭浏览器后再打开，需要重新登录**，不会自动以上次那个账号进入系统；
> - 同一标签页内 **按 F5 刷新不受影响**，不会掉登录；
> - 代价：浏览器按标签页隔离会话存储，**新开一个标签页需要重新登录**；
> - 令牌有效期由后端参数 `ees.security.jwt-expire-minutes` 控制（默认 **480 分钟 / 8 小时**），
>   到期后系统自动清除登录态并回到登录页；
> - 登录页的**「记住用户名」不受影响**（它只记用户名、不记密码，仍长期保存在本机）；
>   右上角头像菜单的**「退出登录」**行为不变，属于主动退出。
> - 由旧版本升级后**第一次打开也需要重新登录一次**：系统启动时会清掉旧版本遗留在本机浏览器中的登录信息。

## 二、综合驾驶舱

进入系统后的默认页面，只展示当前用户已授权的数据。

- **指标卡片**：项目数、评估任务（成功/失败/运行中）、数据快照、评估结果（已发布数）、平均得分、可用算法。
- **任务告警**：失败或超时的任务会以红色告警条列出，点击可直接进入任务详情查看失败原因。
- **趋势与分布**：最近 7 天任务量趋势折线图；评判等级分布环形图（等级颜色：优=绿、良=蓝、中=橙、差=红）。
- **最新评估结果**：点任意一行进入结果分析页。
- **项目态势**：各项目的任务数、结果数与平均得分。
- **算法使用情况**：各算法及其版本的结果统计，用于确认算法版本可追溯。

顶部项目选择框可把驾驶舱切换到单个项目的视角。

## 三、项目管理

1. **新建项目**：填写项目名称（必填）、项目编码（可留空由系统自动生成 `PRJ-yyyyMMdd-####`）、
   项目类型、负责人、所属单位、起止日期与说明。
2. **编辑 / 归档 / 启用**：已归档项目仍保留全部历史结果。
3. **成员配置**：为项目添加成员并指定项目内角色
   （MANAGER 管理 / DATA 数据 / EVALUATOR 评估 / REVIEWER 审核 / VIEWER 查看），
   成员只能看到自己参与的项目数据。
4. **查看统计**：任务数、结果数、数据批次、已发布结果与平均得分。
5. **删除**：已产生评估结果的项目不允许删除，系统会提示改用归档。

## 四、指标体系

> 系统只负责指标体系的**导入、校验、版本化和使用**，不提供从零设计指标体系的页面。
> 导入后的原始版本只读保存，可基于某个版本配置映射与评估参数，但不能覆盖原始版本。

### 4.1 准备导入文件

点击 **下载导入模板** 得到 `指标体系导入模板.xlsx`，或参考 `samples/指标体系样例.csv`。

| 字段 | 必填 | 说明 |
|---|---|---|
| `indicator_code` | 是 | 指标编码，唯一，是数据关联的主键 |
| `indicator_name` | 是 | 指标名称 |
| `parent_code` | 否 | 上级指标编码，顶层留空 |
| `level` | 否 | 层级，可由系统按 `parent_code` 自动推导 |
| `unit` | 否 | 计量单位，需与试验数据单位一致 |
| `direction` | 是 | `POSITIVE` 正向 / `NEGATIVE` 负向 / `INTERVAL` 区间型（也接受 正向/负向/区间型） |
| `weight` | 否 | 本地权重（0~1）；缺省时按同层等权处理并给出告警 |
| `min_value` / `max_value` | 否 | 标准化上下界；缺省时由本批数据推断并在结果中标注 |
| `interval_lower` / `interval_upper` | 区间型必填 | 区间型指标的最优区间 |
| `optimal_value` | 否 | 最优值 |
| `score_rule` | 否 | 评分规则（JSON 文本） |
| `sort_order` | 否 | 排序 |
| `remark` | 否 | 备注 |

### 4.2 导入与校验

1. **指标体系 → 导入指标体系**，选择文件（XLSX / XLS / CSV）、归属项目、版本名称。
2. 校验规则：
   - 指标编码不能为空、不能重复；
   - 上级指标必须存在，且层级不能循环引用；
   - 最小值必须小于最大值；
   - 方向必须合法，区间型必须给出区间上下界；
   - 同层权重之和不为 1 时给出告警，评估时按配置归一化并记录归一化前后权重。
3. 导入结果区显示 总行数 / 成功 / 错误 / 指标数 / 叶子数 / 层级数，以及错误与告警明细
   （含行号与字段）。存在错误行时版本状态为「草稿」，可修正后重新导入。
4. **发布** 版本后，评估任务才能引用它。已发布版本不允许删除，只能归档。

### 4.3 查看指标

版本详情页提供三个标签：

- **指标树**：按层级展开，节点显示编码、方向、单位与权重。
- **指标列表**：支持列排序与关键字过滤，可查看最小值/最大值/区间与评分规则；可导出为 CSV/JSON。
- **导入批次**：记录每次导入的文件、行数、成功/错误行数与错误明细，用于追溯。

## 五、数据接入

系统支持两种数据源接入方式，二者都生成统一的**数据批次**，再生成**数据快照**。
评估人员与系统管理员**两种方式都可用**：数据库抽取见 5.1，文件导入见 5.2。

### 5.1 数据库接入（甲方业务库，只读）

> **评估人员同样可用，不需要等管理员代配数据源**：侧栏「数据接入 → 数据源管理」对评估人员与系统管理员都可见，
> 可自行走完「新建数据源 → 连接测试 → 表清单 / 字段预览 → 单条 SELECT 抽取 → 生成数据批次」全流程。

1. **数据源管理 → 新建数据源**：
   - 数据库类型（MySQL / PostgreSQL / Oracle / SQL Server / 达梦 / 人大金仓 / 通用 JDBC）；
   - JDBC 地址与驱动类（选择类型后自动填充示例）；
   - **只读账号**与密码（密码使用 AES 加密保存，页面不回显）。
2. **连接测试**：显示数据库产品与版本、驱动、URL、是否只读与耗时。
3. **表清单**：读取可用的表与视图。
4. **字段预览**：查看列名、类型、注释、是否可空与样例值。
5. **数据抽取**：
   - 选择目标项目与**校验依据的指标体系版本**；
   - 填入**单条 SELECT** 查询；
   - 点击 **校验 SQL** 进行只读检查。系统会拒绝 `INSERT/UPDATE/DELETE/DROP/TRUNCATE/ALTER/CREATE` 等
     写操作关键字、多条语句与注释，并拒绝非 SELECT 语句；
   - 执行抽取后生成数据批次，抽取行数受数据源的 `maxRows` 限制，超出时给出截断提示。

> **安全边界**（页面页头同样声明）：只允许**单条 SELECT** 查询，**禁止任何写操作**，
> 连接具有**超时与行数上限**，抽取结果直接落为受同一套数据质量校验约束的数据批次。
>
> **密码掩码提醒**：数据源里保存的是外部业务库的 JDBC 地址与账号，**密码字段加密保存且接口不回显**——
> 列表页只显示掩码，页面提示「数据源密码加密保存，页面仅显示掩码，不会回显明文」。
>
> **删除权限提醒**：`data:source:update` 同时管着**编辑与删除**（后端删除接口用的是同一个权限码），
> 因此**评估人员现在也可以删除数据源**；如需收回该能力，需按变更管理流程调整角色权限。

### 5.2 文件导入

1. **数据接入 → 下载数据模板**，或参考 `samples/试验数据样例.csv`。

| 字段 | 必填 | 说明 |
|---|---|---|
| `project_code` | 是 | 项目或试验项目编码 |
| `object_code` | 是 | 被评估对象或方案编码 |
| `object_name` | 否 | 对象名称 |
| `data_time` | 否 | 数据采集或评估时间（支持多种格式，也支持 Excel 日期序列号） |
| `indicator_code` | 是 | 与所选指标体系版本中的编码对应 |
| `indicator_value` | 是 | 原始指标值（数值） |
| `unit` | 否 | 数据单位，需与指标定义一致 |
| `source_batch` | 否 | 来源批次 |
| `remark` | 否 | 补充说明 |

2. 上传文件后选择归属项目与校验依据的指标体系版本，提交导入。
3. 系统执行七类质量校验：

| 规则 | 级别 | 处理方式 |
|---|---|---|
| 必填字段缺失（对象编码、指标编码） | **阻断** | 阻止任务提交，展示缺失字段与记录位置 |
| 缺失值 | **阻断** | 按缺失值策略处理，不允许静默处理 |
| 指标未覆盖 | **阻断** | 数据未覆盖指标体系必需指标时阻止提交 |
| 方向未确认 | 告警 | 未确认方向的指标不得执行需要标准化的算法 |
| 数值格式非法 | 按行错误 | 标记该行错误并提供修正建议，不影响批次内其他有效行 |
| 指标值越界 | 告警 | 超出指标体系定义的上下界时提示 |
| 重复记录 | 告警 | 按批次、对象、时间、指标编码识别 |
| 单位不一致 | 提示 | 数据单位与指标定义不一致时提示 |

4. **质量报告**：显示总行数、有效/错误行数、对象数、指标数、缺失值数、越界数、
   单位不一致数、格式非法数、必填缺失数与重复数，以及是否阻断及阻断原因。
5. **错误明细**：可在线查看并**导出为 Excel**，含行号、对象编码、数据时间、指标编码、
   指标值、单位与错误说明。
6. **重新校验**：修正规则或数据后可重新执行校验。

### 5.3 数据快照

1. **数据快照 → 生成快照**，选择数据批次与指标体系版本（默认取批次已绑定的版本）。
2. 生成过程：读取批次有效记录 → 按指标体系的方向与上下界计算标准化值 →
   标记缺失与越界 → 计算内容校验值（SHA256）→ 落库。
3. 快照包含记录数、对象数、指标数、缺失数、越界数、数据时间范围与质量报告
   （含每个指标实际使用的标准化区间）。
4. **快照在任务执行后保持不变**：历史结果不会因源数据后续变化而被覆盖。
   已被任务使用的快照不允许删除。
5. **快照概览**可按对象查看原始值与标准化值，用于人工核对。

> 同一次快照内，若同一对象同一指标存在多条记录，系统保留**时间最新**的一条，
> 并在质量报告的 `duplicateResolved` 中记录条数。

## 六、评估工作台（分步引导）

### 步骤一：选择项目与指标体系
选择项目，再选择该项目的指标体系版本。系统显示版本状态、指标数与层级；
非「已发布」版本会给出提示。

### 步骤二：选择数据快照
按项目过滤快照，显示记录数、对象数、指标数、缺失数与越界数。
若所选快照绑定的指标体系版本与步骤一不一致，系统会阻止继续并提示重新生成快照。

### 步骤三：选择算法与配置参数

| 算法 | 用途 | 参数 |
|---|---|---|
| **加权平均法** | 对标准化指标综合评分与排序 | 等级名称、等级阈值（降序） |
| **模糊综合评判** | 输出完整综合评判向量与评判等级 | 评语集名称、等级量化分数、合成算子 |
| **层次分析法 AHP** | 计算层级指标权重并做一致性检验 | 指标编码列表、判断矩阵、一致性阈值、是否允许 CR 不通过时强制计算 |
| **组合评估流程** | 先 AHP 计算权重，再驱动加权平均法或模糊综合评判 | 组合流程（阶段一 AHP + 阶段二算法）、判断矩阵 |

**模糊综合评判的合成算子**

| 算子 | 数学形式 | 特点 |
|---|---|---|
| `M_PLUS`（默认） | M(·,+) 加权平均型 | 兼顾全部指标，结果最平稳 |
| `M_MIN_MAX` | M(∧,∨) 主因素决定型 | 由最关键指标决定结果 |
| `M_PLUS_MAX` | M(·,∨) 主因素突出型 | 突出主要指标的影响 |
| `M_MIN_PLUS` | M(∧,⊕) | 取小后求和 |

**AHP 判断矩阵录入**
- 网格编辑，对角线固定为 1，非对角元素按 `a(i,j) × a(j,i) = 1` 校验互反性；
- 「生成互反矩阵」按钮可由上三角自动填写下三角的倒数；
- 一致性检验：CR = CI / RI，CR < 0.1 视为通过；不通过时默认阻止正式评估并提示修正，
  是否允许强制计算由系统参数 `algorithm.allow.force` 控制。

### 步骤四：确认并提交
核对项目、指标体系版本、数据快照、算法与算法版本、参数 JSON，填写任务名称后提交。

### 步骤五：执行跟踪
- 页面每 1.5 秒刷新任务进度与当前步骤；
- 任务状态机：草稿 → 校验中 → 已排队 → 运行中 → 成功、失败或已停止 → 待审核 → 已发布 → 已归档；
- 成功后可跳转到结果分析；失败时显示错误码与错误原因，并可直接**重试**
  （重试会生成新的执行实例，保留原任务记录）。

## 七、结果分析

结果分析页把文本、表格、图形三类展示组织在三个标签页中，
**三者使用同一份后端结果数据集**，前端不做任何数值重算。

### 7.1 文本
- 综合结论：对象、所用算法、综合得分、评判等级与排名；
- 薄弱指标 / 优势指标：按贡献值排序的前三项，便于定位改进方向；
- 改进建议：得分低于 80 分且权重较高的指标，附具体提升建议；
- 若算法为模糊综合评判，展示**完整综合评判向量**（各评语隶属度与占比），
  而不只展示最大隶属度对应的等级。

### 7.2 表格
指标明细表支持排序、筛选与分页，列为：
指标编码、指标名称、单位、方向、原始值、标准化值、权重、贡献值、得分、单指标等级、备注；
表尾给出权重与贡献值合计，可一键导出为 Excel。

### 7.3 图形（八类）

| 图形 | 展示内容 | 交互 |
|---|---|---|
| 柱状图 | 指标得分、贡献值与权重对比（按得分降序） | 按得分排序，分类筛选 |
| 折线图 | 同一项目/对象的多批次评估趋势 | 时间与对象筛选 |
| 饼图 / 环形图 | 指标权重构成 + 评判等级分布 | 显示数值与比例、图例 |
| 雷达图 | 多维度能力对比 | 支持多对象叠加 |
| 散点图 | 两项指标关系 | 可选择横纵轴指标，悬停查看明细 |
| 热力图 | 指标 × 对象得分矩阵 | 颜色图例、单元格查看 |
| 箱线图 | 指标得分分布（中位数、四分位、离群点） | 离群点单独标记 |
| 排名条形图 | 对象综合得分排名 | 并列名次，按等级着色 |

每张图都标注**单位**与**数据来源**，并可单独导出 PNG。当数据不足以生成某类图形时，
系统显示具体原因与补充数据要求，而不是展示误导性的空图。

### 7.4 可追溯信息
展示任务编号/名称、项目、指标体系版本、数据快照、算法与算法版本、提交人、
各阶段时间与耗时、任务状态，以及完整的算法参数与输入摘要 JSON，
满足「每个结果都能反查到项目、指标体系版本、数据源、导入批次、数据快照、
算法名称、算法版本、参数、操作人、开始/结束时间与错误信息」的要求。

### 7.5 复核与发布

> 结果**复核、发布与横向对比均由评估人员与系统管理员执行**：评估人员不必等管理员介入，
> 即可自己走完「执行评估 → 复核 → 发布」闭环；归档与发布同属结果状态流转，权限一致。

| 动作 | 说明 |
|---|---|
| 提交审核（`SUBMIT`） | 结果标记为待审核，任务状态变为待审核 |
| 通过（`APPROVE`） | 审核通过 |
| 退回（`REJECT`） | 结果退回，同时取消发布状态 |
| 发布（`PUBLISH`） | 已退回的结果不允许发布，需重新执行评估 |
| 归档（`ARCHIVE`） | 结果归档保留 |

### 7.6 导出
- **Excel**：三个工作表（报告信息 / 对象综合结果 / 指标明细）；
- **Word**：任务信息、综合评估结果、指标明细与可追溯信息；
- **PDF**：A4 排版，含任务信息、综合结果表与指标明细表（超过 800 行时提示改用 Excel）。

导出内容均带项目、任务、版本与生成时间，并记录在报告导出记录中（含导出人、次数与状态）。

> 本页的导出按钮由 `result:export` 控制，**评估人员与系统管理员都可用**（不要与「报告导出」模块混为一谈）。
> 导出是两步：先 `POST /api/evaluation-results/{id}/exports` 生成报告，再 `GET /api/reports/{id}/download`
> 取回文件；这两步都不依赖 `report:*` 权限，因此报告导出收紧为仅系统管理员后，
> **评估人员的结果导出（Excel / Word / PDF）不受影响**。导出的文件仍会记入报告导出记录，
> 但报告导出记录页面本身只有系统管理员能打开。

## 八、报告导出（仅系统管理员）与算法基准

### 8.1 报告导出记录（仅系统管理员）
按项目、格式与任务过滤已生成的报告，可查看详情并下载。
状态为「生成中 / 就绪 / 失败」，失败时显示具体错误原因。

> **本模块仅系统管理员可用**：评估人员的侧栏不显示「报告导出」，也不持有 `report:list` / `report:create` /
> `report:download` 三项权限，直接访问 `/reports` 会被拦截，调用 `GET /api/reports`（列表）或
> `POST /api/reports`（生成）会返回 HTTP **403** `{"code":2003,"message":"无权访问该资源"}`。
> 「任务详情」页的「导出报告」按钮同样只对系统管理员显示（它走 `POST /api/reports`，需 `report:create`）。
> 评估人员如需导出结果，请使用「评估结果」页的导出 Excel / Word / PDF（见 7.6 节），该能力保持不变。

### 8.2 算法基准测试

系统预置四个标准样例：

| 编号 | 样例 | 预期 |
|---|---|---|
| `BASE-AHP-001` | AHP 完全一致矩阵（3 阶） | 权重 [0.6, 0.3, 0.1]，λmax = 3，CR = 0 |
| `BASE-AHP-002` | AHP Saaty 经典 5 阶矩阵 | 权重约 [0.2636, 0.4758, 0.0538, 0.0981, 0.1087]，CR ≈ 0.0163 通过 |
| `BASE-FUZZY-001` | 模糊综合评判一级模型 | 综合评判向量 [0.46, 0.31, 0.19, 0.04]，等级「优」，得分 85.55 |
| `BASE-WEIGHTED-001` | 加权平均法正向指标归一 | 标准化值 [0.9, 0.8, 0.7]，综合得分 83.0，等级「良」 |

点击 **运行** 会逐字段比对实际输出与预期输出，按绝对/相对容差判定通过与否，
并显示每个字段的期望值、实际值、差值与相对误差；**全部运行** 给出通过率汇总。
这套机制用于向甲方证明「算法实现与基准结果一致」，并提供可复核的测试记录。

## 九、系统管理

### 9.1 用户管理
新建/编辑用户（用户名、姓名、角色、所属单位、邮箱、手机、状态、备注）、
重置密码、启用/停用、删除（内置 `admin` 不可删除）。

### 9.2 角色权限
查看两类角色的权限编码、数据范围与用户数，以及每个角色可访问的页面域。
角色权限由系统预置，如需调整请通过变更管理流程。

### 9.3 审计日志
记录登录、数据、任务、配置与导出五类操作，包含用户、时间、来源 IP、请求方法/路径、
结果、耗时、失败原因与请求摘要，可展开查看详情。
普通用户不能删除日志；系统管理员可按保留天数清理过期日志。

### 9.4 系统参数
按分组维护算法、数据、导出、报告、安全相关参数，例如：

| 参数 | 说明 |
|---|---|
| `algorithm.cr.threshold` | AHP 一致性比率阈值 CR |
| `algorithm.allow.force` | CR 不通过时是否允许强制计算 |
| `algorithm.score.scale` / `display.scale` | 计算与展示保留小数位 |
| `data.missing.policy` | 缺失值策略：`BLOCK` 阻止 / `IMPUTE` 补值 / `DROP` 剔除 |
| `data.duplicate.policy` | 重复记录策略 |
| `export.max.rows` | 单次导出最大行数 |
| `security.login.maxfail` / `lockmin` | 登录失败阈值与锁定时长 |
| `audit.retention.days` | 审计日志保留天数 |

页面底部可维护**数据质量规则**的严重级别（阻断/告警/提示）与启用状态，
调整后立即对后续导入生效。
