## 2. 逐文件详解

### 2.1 `frontend/src/views/indicator/IndicatorVersionList.vue`

**作用**：指标体系版本的管理入口页。一个「指标体系版本」= 一次导入产生的一份只读指标体系快照，本页负责它的列表、导入即校验、校验结果查看、状态流转（草稿 / 已校验 / 已发布 / 校验不通过 / 已归档）与删除。
**被谁使用**：路由 `/indicators`（`docs/API.md` §10「指标体系」）；页面内通过 `router.push('/indicators/:id')` 跳到 2.2 的详情页；被其它页面间接依赖的是同一批接口（`indicatorApi`）。
**关键设计点**：
1. **导入即校验、原始版本只读**：页面把「上传」与「校验」合成一步（`indicatorApi.import` 直接返回 `errors[] / warnings[] / successRows`），前端不提供任何修改已导入指标数据的入口，与页面头部描述「系统只负责指标体系的导入、校验、版本化和使用，不负责重新设计指标体系」一致（对应方案 5.1 指标体系只读管理要求）。
2. **导入结果面板按成功 / 失败两态渲染**：用 `importResult` 是否有值切换「表单态」与「结果态」，结果态再把 `errors` 与 `warnings` 分成两张表，避免把阻断级错误与提示级告警混在一起（对应方案 5.3 数据质量分级）。
3. **后端以 TEXT 保存 `validateResult`**，页面读取时必须走 `parseJson`，否则只能看到 JSON 字符串（后端落库位置见 `IndicatorService` 第 360 行 `version.setValidateResult(JsonUtils.toJson(validateResult))`）。

### 2.2 `frontend/src/views/indicator/IndicatorVersionDetail.vue`

**作用**：单个指标体系版本的详情工作台。上方是版本元数据与统计卡，中间是「指标树 / 指标列表 / 导入批次」三个 tab，下方是校验结果；同时提供重新校验、发布与纯前端 CSV 导出。
**被谁使用**：路由 `/indicators/:id`（由 2.1 的「查看详情」与导入结果面板的「查看版本详情」进入）。
**关键设计点**：
1. **三个 tab 承载三种查询需求**：`/tree` 看层级结构、`/indicators` 看平铺明细（可排序 / 过滤）、`/import-batches` 看导入追溯，三者都在 `loadAll` 中并行拉取，切换 tab 不再发请求（对应方案 5.4 可追溯要求）。
2. **树节点点击 → 指标列表筛选**是刻意的联动设计：树适合「按层级找指标」，列表适合「看明细字段」，但让用户手动复制编码再去列表里搜体验很差，所以点击节点后自动把该编码写入筛选关键字并**自动切到「指标列表」tab**。
3. **导出指标不调用后端**：指标数据已在内存里，直接在前端拼 CSV 并加 UTF-8 BOM，既省一次接口又保证 Excel 打开中文不乱码（离线环境下用户最常用的就是 Excel）。

### 2.3 `frontend/src/views/data/DataSourceList.vue`

**作用**：数据源管理页。负责接入甲方业务库的全部只读操作：连接测试、表清单与字段预览、以单条 SELECT 抽取数据并自动生成数据批次；以及数据源的新建 / 编辑 / 删除。
**被谁使用**：路由 `/data-sources`；本页抽取产生的数据批次会在 `/data-batches`（2.4）里出现，页面用 `#/data-batches` 链接直接引导过去。
**关键设计点**：
1. **只读约束在前后端双重表达**：页面头部描述与抽取弹窗的信息条都写明「仅允许单条 SELECT / WITH、禁止写操作关键字与 SQL 注释、受超时与行数上限约束」，与后端 `DataSourceService.validateReadOnlySql`（L335–363）逐条对应；服务端还强制 `ds.setReadOnly(true)`，前端不提供任何开关。
2. **`validateSql` 作为即时只读校验**：后端专门提供 `POST /api/data-sources/validate-sql`（`DataSourceController` L130–144，注意该端点**没有** `@PreAuthorize`），让用户在执行抽取前就知道 SQL 是否合规，避免「点了执行才报错」。
3. **密码永不回显**：列表接口把密码置空、详情接口返回掩码 `******`，编辑时保持 `******` 不变即沿用原密码，与后端 `save` 的掩码判断一一对应。

### 2.4 `frontend/src/views/data/DataBatchList.vue`

**作用**：数据接入工作台。一个「数据批次」= 一次数据导入 / 抽取的结果集合，本页负责文件导入、质量报告（11 项计数 + 阻断结论）、错误明细、原始数据预览、重新校验、删除，以及**由批次生成数据快照**。
**被谁使用**：路由 `/data-batches`；被 2.3 的抽取结果面板用 `#/data-batches` 链接引导进入；本页的「生成数据快照」最终产物出现在 2.5 的 `/snapshots`。
**关键设计点**：
1. **质量报告是「导入结果面板」与「质量报告弹窗」的同一套视图**：两处都把 11 个计数做成 `StatCard`、都用 tag 表达 `blocking`、都用 `el-alert type="error"` 逐条列出 `blockingReasons`。一致性来自「同一份报告、两种入口」的设计（对应方案 5.3 数据质量校验与分级阻断）。
2. **`parseJson` 处理 `qualityReport` / `errorDetail`**：批次详情接口返回的两个字段是 JSON **字符串**（后端 `batch.setQualityReport(JsonUtils.toJson(...))`，`DataBatchService` L185–187），必须解析后才能用。
3. **快照生成的版本默认值来自批次**：批次自身记录了导入时绑定的 `targetVersionId`，生成快照时默认沿用，用户只在需要对比时才切换版本。
4. **两个「指标体系版本」下拉为空时必须解释原因**（本次提交 `f8956fe` 新增的两条 `el-alert`，`DataBatchList.vue` 现为 1136 行）：指标体系版本在**导入时绑定项目**（导入表单里的「关联项目」留空即公共版本），所以「目标项目 / 批次所属项目」一旦是没绑定过版本的项目，版本下拉就是空的——这是数据状态问题，不是功能故障。两处 warning 分别落在导入弹窗（`v-if="importForm.projectId && !versions.length"`，L150–159）与生成快照弹窗（`v-if="!versions.length"`，L457–465），文案统一落在「去哪导入、怎么让版本对所有项目可见、下一步做什么」，与后端 `GET /api/indicator-versions/options` 的行为严格一致（不传 `projectId` 返回全部版本，传了按项目过滤）。

**易错点/注意**
1. 导入结果的错误明细上限（200）与质量报告弹窗的上限（500）不同，这不是笔误：前者是后端 `import` 接口的返回裁剪（`DataBatchService` L201），后者是落库 `errorDetail` 的裁剪（L186–187）。界面上两处的标题文字也分别写明了对应上限。

### 2.5 `frontend/src/views/data/SnapshotList.vue`

**作用**：数据快照管理页。列表展示快照及其统计，抽屉式「快照概览」把快照的元数据、质量报告、对象 / 指标清单与按对象分组的快照值（原始值 + 标准化值）摊开展示；同时提供生成快照入口与删除。
**被谁使用**：路由 `/snapshots`；2.3 的抽取结果、2.4 的导入结果与快照生成成功面板都用 `#/snapshots` 引导到本页；本页生成 / 查看的快照随后被评估工作台选用（另一分册）。
**关键设计点**：
1. **快照是不可变凭证**：概览里展示 `checksum`（SHA-256）与 `qualityReport`，加上「已被任务使用不允许删除」的约束，共同支撑「历史评估结果可追溯、不被源数据变化覆盖」（对应方案 5.4 可追溯要求，后端 `SnapshotService` 类注释亦如此声明）。
2. **概览数据分两级请求且互不拖累**：`overview` 接口只返回前若干对象的快照值用于快速首屏，`values` 接口返回全量值用于逐对象查看；两者用 `Promise.all` 并行，**后者失败不影响前者**（`.catch(() => null)`）。
3. **`USED` 状态的双重保护**：按钮 `:disabled` + 禁用的 tooltip 说明 + `remove()` 内的提前 return，与后端 `SnapshotService.delete` 的 `"USED".equals(...)` 判断（L310–311）形成三层一致。

**易错点/注意**
1. `overview` 与 `values` 的关系是「快 + 全」而不是「主 + 备」：正常路径下 `allValues` 用的是 `values` 的全量结果，`overview.values` 仅作为降级数据。因此**按对象切换时的完整性依赖 `values` 接口**，若该接口持续失败，用户会看到「对象下拉里有 N 个对象、但切换后某些对象没有数据」——这属于预期的降级行为，不是 bug。
2. `<span>` 包裹禁用按钮不是冗余结构：去掉它 tooltip 就不再显示，`USED` 的用户会只看到一个灰按钮而不知道为什么。
3. `openCreate` 拉批次只取前 100 条（`size: 100`），是刻意的性能取舍：候选里没有更早的批次时，用户应改从「数据批次」页的「生成数据快照」进入（那条路径天然带着批次上下文）。

### 2.6 五页统一约定：loading、空数据、失败处理与权限码

#### 2.6.1 loading

| 约定 | 实现 | 出现位置（示例） |
|---|---|---|
| 列表加载 | `v-loading="loading"` 绑定在 `el-table` 上 | 五个页面的主表格全部如此 |
| 请求状态标志 | 每个加载函数 `loading.value = true` → `try/catch/finally` → `finally` 中复位 | 五页所有 `load*` 函数 |
| 按钮级 loading | 每个写操作一个独立 ref，`:loading` 绑定 | `templateLoading`、`importing`、`revalidating`、`saving`、`extracting`、`sqlChecking`、`exporting`、`downloading`、`snapSaving`、`createSaving` |
| 弹窗内容级 loading | 弹窗**先打开**再置 loading，`v-loading` 加在内容区 `div` 上 | 2.3 `testLoading`、`tablesLoading`、`fieldsLoading`；2.4 `qualityLoading`、`errorsLoading`、`previewLoading`；2.5 `overviewLoading` |
| 并行加载 | `Promise.all` 合并互不依赖的请求，缩减首屏时间 | 2.2 `loadAll`、2.3 `onMounted`、2.5 `openOverview` |

**注意**：所有 `finally` 都会复位 loading。这是刻意的——漏一个 `finally` 就会让蒙层永久驻留，页面看起来像卡死。

#### 2.6.2 空数据

本项目在这 5 个页面里**没有使用 `el-empty` 组件**，而是用全局样式类 `.ees-empty`（`frontend/src/styles/index.scss` L125–129：居中、灰字、上下 32px 留白）或 `el-table` 的 `empty-text` 属性实现同样效果：

| 形式 | 位置 |
|---|---|
| `.ees-empty` 区块（带行动建议） | 2.1 L297；2.2 L100、L303；2.3 L34、L128；2.4 L41–44；2.5 L37–40 |
| `empty-text`（表格内空态） | 2.1 L48、L193、L213、L268、L283；2.2 L123、L158、L183、L189、L274、L289；2.3 L158；2.4 L231、L323、L356、L391；2.5 L205、L247 |
| 下拉 / 区域的空提示 | 2.4 L150–159、L457–465（两个「指标体系版本」下拉为空时的 warning 说明，见 2.4.1）；2.5 L221、L226（无对象 / 无指标）、L273（未选对象） |

统一原则：**空态必须给下一步动作**，例如「暂无数据源，请点击"新建数据源"…」「该版本暂无校验结果，可点击「重新校验」生成」，而不是只说「暂无数据」。（`el-empty` 组件在本项目其它页面确实有使用，例如 `Dashboard.vue` L197、`TaskDetail.vue` L202，本册这 5 个页面统一走轻量的 `.ees-empty`。）

#### 2.6.3 请求失败处理

失败处理全部由 Axios 响应拦截器统一承担（`frontend/src/api/request.ts` L56–106）：

| 场景 | 拦截器行为 | 页面侧配合 |
|---|---|---|
| 业务失败（`code !== 0`） | `ElMessage.error(body.message)` 并 reject | 页面的 `catch {}` **留空或只清空数据**，不重复提示（多处已写注释「统一响应拦截器已提示」「错误提示由统一请求层给出」） |
| HTTP 401 | 清 token + 弹「登录状态已失效」并跳登录页 | 页面无需处理 |
| HTTP 403 | 提示「无权访问该资源」 | 页面通过 `userStore.has(...)` 提前隐藏按钮，避免触发 403 |
| 请求超时 | 提示「请求超时，请稍后重试…」 | 上传 / 下载接口在 `http.upload` / `http.download` 里把超时放宽到 600s |
| 非致命失败需降级 | — | 2.4 `dataBatchApi.get(id).catch(() => null)`、2.5 `snapshotApi.values(id).catch(() => null)`——**把可失败的次要请求降级为 null，不让主流程一起失败** |

页面侧 `catch` 的三种写法及用途：① 空 `catch`（写操作失败，靠拦截器提示）；② `catch { rows.value = []; total.value = 0 }`（列表失败后清空，避免展示过期数据）；③ `catch { x.value = { valid:false, message: errMsg(e) } }`（2.3 `validateSql`、`openTest`：把错误消息落到界面控件里，让用户能持续看到失败原因）。

#### 2.6.4 权限码一览（与后端 `@PreAuthorize` 的一致性）

判定入口：`useUserStore().has(code)`（`frontend/src/stores/user.ts` L30–36）——超级管理员（`superAdmin === true` 或 `roleCode === 'SYSTEM_ADMIN'`）一律放行；权限数组含通配符 `*` 一律放行；否则按数组精确匹配。后端注解形态统一为 `@PreAuthorize("hasAuthority('xxx') or hasRole('SYSTEM_ADMIN')")`，两侧语义一致。

| 页面 | 前端权限码（`userStore.has`） | 控制的 UI | 对应后端接口与注解 |
|---|---|---|---|
| 2.1 IndicatorVersionList | `indicator:import` | 页头「导入指标体系」；行内「重新校验 / 发布 / 归档 / 删除」 | `POST /indicator-versions/import`、`POST /{id}/revalidate`、`POST /{id}/publish`、`POST /{id}/archive`、`DELETE /{id}`（`IndicatorController` L84–117，全部 `indicator:import`） |
| 2.2 IndicatorVersionDetail | `indicator:import` | 页头「重新校验 / 发布」 | 同上（`POST /{id}/revalidate`、`POST /{id}/publish`） |
| 2.3 DataSourceList | `data:source:create` / `data:source:update` / `data:source:test` / `data:source:extract` | 「新建数据源」/ 「编辑 · 删除」/ 「连接测试」/ 「数据抽取 · 执行抽取」 | `POST /api/data-sources`（create）、`PUT`+`DELETE /{id}`（update）、`POST /{id}/test`（test）、`POST /{id}/extract`（extract）（`DataSourceController` L68–127） |
| 2.4 DataBatchList | `data:batch:import` / `data:batch:validate` / `data:batch:delete` / `data:snapshot:create` | 「导入数据文件」/（更多）「重新校验」/（更多）「删除」/（更多）「生成数据快照」 | `POST /api/data-batches/import`、`POST /{id}/revalidate`、`DELETE /{id}`、`POST /api/snapshots`（`DataBatchController` L57–93、`SnapshotController` L57） |
| 2.5 SnapshotList | `data:snapshot:create` | 「生成快照」+ 行内「删除」 | `POST /api/snapshots`、`DELETE /api/snapshots/{id}`（`SnapshotController` L57、L68，两者同权限码） |

**只读接口不做页面级判权**：五页读取列表 / 详情 / 树 / 字段 / 概览等只读接口分别需要 `indicator:list`、`data:source:list`、`data:batch:list`、`data:snapshot:list`，但页面**没有**为它们加 `v-if`——页面可见性由路由与菜单层控制，能进入页面即已具备。少数未加注解的只读端点（`GET /api/data-sources/db-types`、`POST /api/data-sources/validate-sql`、`GET /api/data-batches/template`、`GET /api/indicator-versions/options` 与 `/api/indicator-versions/template`）仍受登录过滤链保护。此外 2.2 的 `projectApi.get` 需要 `project:list`，2.3/2.4/2.5 的 `projectApi.options` 与 `indicatorApi.options` 属免注解的只读下拉接口。

## 3. 本册小结

- 本册共覆盖 **5 个文件、4365 行代码**（753 + 734 + 931 + 1136 + 811），全部为 `<script setup lang="ts">` 语法的 Vue 3 单文件组件，每个文件都按 `<template>` / `<script setup>` / `<style scoped>` 三段给出了结构表与逐语句说明（每文件 1 个 `###` 小节，下含 3 个 `####` 分段），另加一个跨文件的统一约定小节（2.6）。
- **这一层的职责边界**：五页都是「薄 UI 层」——不实现任何业务规则（指标体系解析、质量规则判定、标准化计算、快照固化全部在后端 Service 里），前端只做四件事：把参数组装成后端契约要求的形状（`FormData`、`?? undefined`）、把后端返回的字典与 JSON 文本渲染成人能读的样子（`format.ts` 字典 + `parseJson`）、按权限码显隐按钮、在写操作前做一次「与后端同规则的提前拦截」。
- **最容易被误解的三处**：① `parseJson` 不是「容错装饰」，而是必需步骤——`validateResult`、`qualityReport`、`errorDetail` 在后端都以 TEXT 存 JSON，不解析就只是一串字符；② 页面的空 `catch {}` 不是漏写错误处理，而是因为统一响应拦截器已经弹过提示，重复弹会被用户视为骚扰；③ 前端的权限判断与状态判断（如「已发布不可删除」「`USED` 不可删除」「`FAILED` 批次不可生成快照」）都是**提前拦截**，后端仍各自有一份权威判断，改前端不会绕过约束。
- **跨页的三条数据链路**（读代码时按这条线走最省力）：指标体系（2.1 导入 → 2.2 校验 / 发布）→ 数据源抽取或文件导入（2.3 / 2.4）→ 数据批次质量报告（2.4）→ 数据快照（2.4 / 2.5）→ 评估任务选用快照（另一分册）。页面之间用 `#/...` 链接互相引导（2.3 → `#/data-batches`，2.4 → `#/snapshots`），正是这条链路的界面化表达。
- **权限码与后端严格同源**：本册用到的权限码共 9 个（`indicator:import`、`data:source:create/update/test/extract`、`data:batch:import/validate/delete`、`data:snapshot:create`），每一个都能在后端 `@PreAuthorize` 中找到同名 `hasAuthority`，且「删除数据源」与「更新数据源」、「删除快照」与「创建快照」这种后端复用同一权限码的地方，前端也复用同一个 `canUpdate` / `canCreate`，没有自造一个更细的码。
