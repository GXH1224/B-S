# 代码详解文档 —— 写作规范（所有分册必须遵守）

> 本文件是《效能评估系统 代码详解》的**统一写作规范**。
> 任何分册在动笔前必须先读本规范，输出必须严格符合下面的结构与格式。

## 一、目标读者与粒度

- 读者：需要读懂、维护、答辩或交接这份代码的开发者与学生。
- 粒度要求：**覆盖分配给你的每一个文件，一个都不能漏**；每个文件内部**逐语句/逐逻辑块**说明。
- 行号必须真实：先用 read 工具读取文件（带行号），再照抄行号区间，禁止凭印象编造行号。
- 允许合并的范围（合并后仍然要解释）：
  - `package` / `import` 连续若干行 → 合并为一行说明「导入了什么、为什么需要」；
  - 纯符号行（`}`、`)`、空行）→ 并入上一块的结束行；
  - 一组连续的字段声明、一组 getter/setter → 可合并为一行说明「这组字段/访问器的作用」。
- 不允许合并的范围：**任何有业务含义的语句**（判断、赋值、调用、异常处理、SQL、模板指令、样式规则的关键项）必须单独一行说明。

## 二、分册文件格式

每份分册是一个 Markdown 文件，结构固定如下：

```markdown
# <分册标题>

> 覆盖范围：<列出目录或文件范围>
> 对应分册：<本文档在总索引中的序号>
> 阅读前提：<需要先了解的内容，如「先读 03 领域模型」>

## 目录
- [1. 文件清单](#1-文件清单)
- [2. 逐文件详解](#2-逐文件详解)
- [3. 本册小结](#3-本册小结)

## 1. 文件清单

| 序号 | 文件路径（相对仓库根） | 行数 | 一句话作用 |
|---|---|---|---|
| 1 | `backend/src/main/java/com/ees/...` | 123 | ... |

## 2. 逐文件详解

### 2.1 `backend/src/main/java/com/ees/xxx/Yyy.java`

**作用**：一句话。
**被谁使用**：被哪些类调用/注入。
**关键设计点**：1~3 条，说明为什么这么写（对应方案哪一条要求）。

| 行号 | 代码 | 说明 |
|---|---|---|
| 1-12 | `package ...` / `import ...` | ... |
| 14 | `@SpringBootApplication` | ... |
| 16 | `public class EesApplication {` | ... |
| 18-20 | `public static void main(String[] args) { SpringApplication.run(...); }` | ... |

**易错点/注意**：可选，1~2 条。

（继续下一个文件……）

## 3. 本册小结

- 本册共覆盖 N 个文件、M 行代码。
- 关键结论 3~6 条（这一层的职责边界、易被误解的地方）。
```

## 三、写作质量要求

1. **准确优先**：不确定的地方必须去读代码确认，禁止猜测。读不到就写「未能确认」，不要编。
2. **解释"为什么"**：不能只把代码翻译成中文。例如
   - ❌ `if (cr > threshold) return failure;` → 「如果 CR 大于阈值就返回失败」
   - ✅ 同上并补充「方案 6.2 要求一致性不通过时阻止正式评估，因此这里直接返回失败结果而不是继续计算」
3. **术语一致**：统一使用这些译名
   - 指标体系 / 指标版本 `indicator version`、数据批次 `data batch`、数据快照 `data snapshot`、
     评估任务 `evaluation task`、评估结果 `evaluation result`、评判等级 `grade/level`、
     综合评判向量 `fuzzy vector`、标准化值 `normalized value`、贡献值 `contribution`、
     一致性比率 `CR`、判断矩阵 `judgment matrix`
4. **中文**：正文全部简体中文；代码、标识符、路径、命令保持原样。
5. **不要复述整段代码**：表格「代码」列只放关键片段或简短签名，不要大段粘贴（完整代码在源文件里）。
6. **表格不要过宽**：把长表达式截断为可识别的片段，细节放在「说明」列。
7. **标注与方案对应关系**：能对应上技术方案章节的，明确写出（如「对应方案 5.4 可追溯要求」）。

## 四、输出要求

- 严格使用 write 工具写入**指定路径**，UTF-8 编码，不要 BOM。
- 只创建分配给你的那一个文件，**不要修改任何其他文件**（尤其是源码）。
- 写完必须自检并在回复中报告：
  - 目标路径；
  - 覆盖的文件数、总行数，并确认与分配清单一致；
  - 每个文件都有 `###` 小节（列出小节标题数量）。
- 若某个文件特别大（>800 行），可以拆成 `### 2.x.1 / 2.x.2` 多个小节，但仍属同一文件，不要漏。
